# Repository Governance

## Purpose

Define the baseline controls for managing changes to this repository.

## Branch Strategy

- `main` is the reviewed and approved baseline.
- Development work must use dedicated feature or fix branches.
- Changes should be submitted through pull requests.
- Direct changes to `main` are prohibited by repository policy.

## Pull Request Principles

- Every change must have a clear purpose.
- Changes should be reviewed before merging.
- Discussions and requested changes should be resolved.
- Automated checks should pass before merging.

## Security

- Never commit credentials or secrets.
- Keep infrastructure environments separate.
- Review security implications before introducing dependencies.
- Document significant architectural decisions.

## Governance Evolution

These standards will evolve as the engineering team and repository mature.
